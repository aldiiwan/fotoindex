# Roadmap and validation

## Available in 0.1.0
Contact sheets, CSV inventory, SHA-256 duplicate flags, read-only originals, tests, English/Indonesian documentation.

## Next: validate before expanding
- Ask 3–5 willing photographers or visual researchers to try one real workflow. This is a project goal, not a program threshold.
- Record consented feedback as issues: OS, collection size, failure, time spent, requested improvement. Do not invent users or testimonials.
- Fix confirmed defects, document the change, and release a new tagged version.
- Test installation on a real Windows machine. CI is complementary evidence, not a substitute for user experience.

## Candidate improvements, pending demand
- Folder picker and progress indicator for nontechnical users.
- PDF contact sheets and editable captions.
- Verified cross-platform Unicode font support.
- Configurable layout and optional color-managed export.
- Separate optional RAW support after resource and decoder testing.

## Program application readiness
No repository structure or star count guarantees acceptance to a grant or subscription program. Apply only with accurate maintainer responsibilities, real use, issue/PR history, and release evidence. The current project is new and has no external adoption evidence. Keep release and maintenance records naturally as work happens; never manufacture activity.
